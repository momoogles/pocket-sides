# おぼえる台本

おぼえる台本は、台本PDFをブラウザ内で読み取り、自分の役のセリフを短いシーンごとに練習するWebアプリです。

## 開発環境

Node.js と pnpm のバージョンは `mise.toml` で固定しています。mise をインストールしたうえで、次のコマンドを実行してください。

```sh
mise install
mise run dev
```

ブラウザで `http://127.0.0.1:5173/pocket-sides/` を開くと、開発中のアプリを確認できます。`mise run dev` は依存関係をインストールしてから開発サーバーを起動します。静的ファイルの生成には `mise run build` を使います。

## 使い方

1. 「PDFを選ぶ」から台本PDFを開きます。文字はブラウザ内で読み取ります。
2. 読み取った文字や役名を元のPDFと見比べ、必要なら直します。
3. 役を選び、「練習を始める」を押します。
4. シーン一覧から練習するシーンを選び、表示された前のセリフやト書きを読みます。
5. 自分のセリフを声に出してから「確認する」を押します。自分のセリフの原文と、原文順で次に続くセリフが表示されます。

シーン一覧では、台本上のシーンごとに短い練習シーンを並べます。長いシーンも、発話ごとに分けて練習できます。練習画面では前後に表示する範囲を調整できます。下の操作欄から前後へ移動したり、同じシーンを繰り返したりできます。「設定を見直す」から役や読み取り結果に戻れます。キーボードの左右キーでも移動でき、右キーで答えを確認できます。

## 台本の扱い

- 台本の権利は著作者等に帰属します。このアプリのMITライセンスは、読み込む台本の利用条件を変更するものではありません。文字の抽出・保存についても、各作品に適用される利用条件や法令に従って扱ってください。
- PDFの読み取り、文字の抽出、役名の候補表示、練習表示はブラウザ内で行います。PDFや台本由来の文字を外部サービスへ送信しません。
- PDFを開いて役を選ぶ間、読み取り結果や設定はメモリ内で扱います。「練習を始める」を押すと、読み取り結果、役名、選んだ役、文字の置き換え、練習範囲、練習するシーンを、この端末のブラウザ内に保存します。画像解析で読み直した結果も、この時点で保存されます。PDFファイル自体は保存しません。
- ホーム画面の「最近おぼえようとした台本」には、選択した役を表示します。「PDFを選んで練習を再開する」を選ぶと、端末から同じPDFを選び、前回の設定でシーン一覧を開けます。PDFの中身から作る照合用の値はブラウザ内で作成します。保存した設定と読み取り結果は、ホーム画面から台本ごと、またはすべて削除できます。
- 練習後に「台本を閉じる」を押すと、最後の練習設定の保存を待ってから閉じます。保存に失敗した場合は、保存せずに閉じるかどうかを確認します。ブラウザやタブを直接終了した場合の保存完了は保証しません。
- 保存にはIndexedDBを使用します。保存内容は利用者の端末のブラウザ内に保管され、公開サイトへ送信されません。同じ端末・同じブラウザプロファイル内では、同一オリジン（スキーム・ホスト名・ポートが同じ配信元）で動く別アプリのJavaScriptも、この保存領域を参照できます。URLのパスでは分離されないため、現在の公開先では `https://momoogles.github.io/` 配下の別のGitHub Pagesサイトもこの範囲に含まれます。共有端末や共用のブラウザでは、練習後に保存内容を削除してください。別アプリから保存領域を分離するには、専用ドメイン等の別オリジンへの移転が必要です。
- アクセス解析、ログイン、外部の解析APIは使用しません。
- PDF.js のワーカー、文字コード表、補助フォント、色変換データ、画像処理用データをアプリに同梱します。読み順と役名の判定では、PDF.jsから得た文字、位置、方向を使います。文字情報が欠けたページでは日本語OCRを補助に使い、判読できる文字は残したまま、文字化けや欠落のある行を読み直した結果で補います。文字情報がないページでは画像解析で文字を読み取ります。いずれも誤りが残る場合があるため、元のPDFと比べてください。
- 読み取り結果に誤認識の可能性がある漢字が含まれる場合、種類数と出現数を表示します。元のPDFと見比べ、正しい字が分かる文字は置き換えられます。置き換えは開いている間の表示に反映され、PDFは変更されません。練習を始めると、置き換えもほかの練習設定と一緒に端末内へ保存されます。
- 役名が見つからない場合は、台本を見ながら役名を追加できます。
- 画面では「画像解析で文字を読み直す」と案内します。Tesseract.jsと同梱の日本語データを使い、ブラウザ内で処理します。読み直した行は元の文字抽出へ戻せます。画像だけのPDFでは、役名、読み順、ト書きの位置を元のPDFと見比べてください。

PDF.jsから得た文字、座標、方向を使って読み順を組み立てます。ページの端にあるページ番号は台本文字から除き、縦書きは発話ごとに複数列をまとめて、ページ番号と列の範囲を表示します。空白は日本語文字や句読点の間で整えます。台本のレイアウトやPDF内の文字情報によって読み順や役名の候補が誤る場合があるため、練習前に元のPDFと照合してください。

## GitHub Pages

このリポジトリ名に合わせて、Vite の公開先を `/pocket-sides/` に設定しています。GitHub リポジトリの Settings → Pages で公開元に「GitHub Actions」を選ぶと、`.github/workflows/deploy.yml` の実行後に公開できます。このワークフローはソースの変更を `main` に push したとき、または Actions 画面から手動実行したときに動きます。

埋め込み画面では、`src/bootstrap.ts` がアプリ本体を起動せず、直接開くためのリンクを表示します。PDFの読込処理やIndexedDBの初期化も行いません。この処理はアプリ側の起動制限です。HTTPレスポンスヘッダーによる埋め込み拒否とは異なり、`frame-ancestors` をmetaタグに書いてもブラウザによる埋め込み拒否は有効になりません。ヘッダーで拒否する場合は、ヘッダーを設定できる配信構成が必要です。

依存ライブラリの導入には pnpm を使用します。画面設計は Apple Human Interface Guidelines のレイアウト原則と、Material 3 の色の役割・文字階層を参考にしています。画面の書体には IBM Plex Sans JP を使用し、Fontsource から取得した WOFF2 と互換用の WOFF をアプリに同梱しています。実行時に Google Fonts など外部のフォント配信サービスへ接続することはありません。ロゴ画像とアイコン素材は使用せず、操作は文字で表示します。
